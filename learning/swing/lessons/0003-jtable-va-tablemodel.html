JTable và AbstractTableModel

Hiển thị danh sách dữ liệu dạng bảng — có lẽ là component bạn sẽ dùng nhiều nhất trong một app quản lý dữ liệu.

Nguồn chính Đọc trước: Oracle — How to Use Tables. Tham khảo API đầy đủ: AbstractTableModel.

1. Ý tưởng cốt lõi: JTable không giữ dữ liệu

Đây là điều gây nhầm lẫn nhất khi mới học JTable: bản thân nó không lưu trữ gì cả. Nó chỉ là một "khung vẽ" — mọi dữ liệu thực sự nằm trong một đối tượng riêng gọi là TableModel, mà JTable liên tục hỏi: "có bao nhiêu dòng?", "có bao nhiêu cột?", "giá trị ở dòng X cột Y là gì?". 

JTable table = new JTable(myModel); // myModel implements TableModel

Bạn hiếm khi cài đặt trực tiếp interface TableModel (có quá nhiều phương thức) — thay vào đó, kế thừa lớp AbstractTableModel, lớp này đã cài sẵn phần "nồi hơi" và chỉ bắt bạn cài 4 phương thức.

2. Viết một TableModel của riêng bạn

public class PersonTableModel extends AbstractTableModel {
    private List<Person> rows = new ArrayList<>();
    private final String[] columns = {"Tên", "Tuổi", "Email"};

    public void setRows(List<Person> rows) {
        this.rows = rows;
        fireTableDataChanged(); // báo cho JTable biết "dữ liệu đổi rồi, vẽ lại đi"
    }

    public Person getRowAt(int index) { return rows.get(index); }

    @Override public int getRowCount() { return rows.size(); }
    @Override public int getColumnCount() { return columns.length; }
    @Override public String getColumnName(int col) { return columns[col]; }
    @Override public Object getValueAt(int row, int col) {
        Person p = rows.get(row);
        return switch (col) {
            case 0 -> p.getName();
            case 1 -> p.getAge();
            case 2 -> p.getEmail();
            default -> null;
        };
    }
}

4 phương thức bắt buộc, không hơn không kém: getRowCount, getColumnCount, getColumnName, getValueAt. Phương thức getRowAt ở trên không phải một phần của TableModel — đó là tiện ích bạn tự thêm để sau này biết dòng đang chọn ứng với đối tượng nào trong danh sách gốc.

3. Gắn vào giao diện

PersonTableModel model = new PersonTableModel();
JTable table = new JTable(model);
panel.add(new JScrollPane(table), BorderLayout.CENTER); // nhớ bọc JScrollPane!

// Khi có dữ liệu mới từ đâu đó (gọi API, đọc DB, ...):

4. Biết người dùng đang chọn dòng nào

int selectedRow = table.getSelectedRow(); // -1 nếu chưa chọn gì
if (selectedRow >= 0) {
    Person selected = model.getRowAt(selectedRow);
    // dùng selected để mở form sửa, xoá, v.v.
}
Lỗi hay gặp Nếu bảng cho phép sắp xếp (table.setAutoCreateRowSorter(true)), getSelectedRow() trả về chỉ số theo thứ tự hiển thị, có thể khác thứ tự trong danh sách gốc. Khi đó phải đổi qua chỉ số gốc bằng table.convertRowIndexToModel(selectedRow) trước khi tra vào rows.
Lỗi hay gặp Quên gọi fireTableDataChanged() (hoặc các biến thể fireTableRowsInserted/fireTableRowsDeleted) sau khi đổi dữ liệu → bảng đứng yên vĩnh viễn dù dữ liệu bên dưới đã đổi. Đây là lỗi phổ biến số một với JTable.

5. Có cần viết tay mọi lần không?

Swing có sẵn DefaultTableModel — nhận thẳng Object[][]/Vector, không cần viết lớp con. Nhanh cho việc thử nghiệm, nhưng mất kiểu dữ liệu (mọi thứ là Object) và không tự nhiên khi dữ liệu gốc là danh sách các object có kiểu rõ ràng (ví dụ List<Person>). Với ứng dụng thật thao tác trên các đối tượng nghiệp vụ, viết một lớp con AbstractTableModel tổng quát (dùng generic <T>, nhận vào danh sách tên cột + cách lấy giá trị từng cột) thường đáng công hơn — viết một lần, dùng lại cho mọi bảng trong ứng dụng.

Kiểm tra nhanh

1. JTable tự nó có lưu trữ dữ liệu hay không?

Đúng — JTable chỉ là lớp vẽ, dữ liệu thật nằm hoàn toàn trong TableModel.
Chưa đúng — nhớ lại mục 1: đây là điểm dễ nhầm nhất khi mới học JTable.

2. Phương thức nào của TableModel quyết định số cột được hiển thị?

Đúng — đây là 1 trong 4 phương thức bắt buộc; getRowCount quyết định số dòng, không phải số cột.
Chưa đúng — đọc kỹ tên phương thức: nó cần khớp với "cột" và "đếm số lượng".

3. Muốn biết đối tượng nào (trong danh sách gốc) tương ứng với dòng người dùng vừa chọn trên bảng, cách làm đúng là gì?

Đúng — table.getSelectedRow() cho chỉ số dòng, dùng nó để tra vào danh sách gốc (qua một phương thức tiện ích như getRowAt).
Chưa đúng — các phương thức kia không liên quan đến việc "dòng nào đang được chọn".

Bài tập thực hành

  1. Định nghĩa một lớp đơn giản Book (title, author, year — cứ 3 field bất kỳ bạn thích).
  2. Viết BookTableModel extends AbstractTableModel hiển thị danh sách Book, đúng theo khuôn mẫu mục 2.
  3. Dựng một cửa sổ: JTable bọc JScrollPane ở giữa, một nút "In sách đã chọn" ở dưới. Nút này, khi bấm, lấy dòng đang chọn qua getSelectedRow() và in tên sách ra console (dùng System.out.println — Bài 4 sẽ thay bằng dialog thật).
  4. Nạp sẵn 4-5 quyển sách mẫu vào model lúc khởi động bằng setRows(...).
  5. Tự kiểm tra:
    • [ ] Bảng hiện đủ tiêu đề cột và dữ liệu ngay khi mở cửa sổ.
    • [ ] Bấm nút khi chưa chọn dòng nào không làm chương trình crash (kiểm tra selectedRow >= 0 trước khi dùng).
    • [ ] Bấm nút khi đã chọn một dòng in đúng tên sách của dòng đó, không phải dòng đầu tiên cố định.
  6. Áp dụng vào project của bạn: với bất kỳ danh sách dữ liệu nào project cần hiển thị (khách hàng, sản phẩm, đơn hàng, ...), đây chính xác là khuôn mẫu bạn sẽ lặp lại: một lớp XyzTableModel theo mục 2, một JTable + JScrollPane theo mục 3. Viết đúng một lần, hiểu rõ, rồi sao chép/điều chỉnh cho từng loại dữ liệu.
Đừng ngại hỏi Nếu bảng hiện trống trơn dù bạn chắc chắn đã nạp dữ liệu, hoặc getValueAt ném IndexOutOfBoundsException, cứ dán nguyên lớp TableModel của bạn ra để được soát lỗi.
