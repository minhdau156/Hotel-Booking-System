Event Listener và JOptionPane

Làm cho giao diện phản ứng lại với người dùng, và hỏi/báo lại cho họ bằng hộp thoại.

Nguồn chính Đọc trước: Oracle — How to Write an Action Listener, Oracle — General Information about Writing Event Listeners, Oracle — How to Make Dialogs.

1. Mô hình chung: đăng ký một "người nghe"

Swing dùng mô hình event listener: bạn đăng ký một đối tượng cài đặt một interface nào đó (ví dụ ActionListener) vào một component, Swing sẽ tự gọi phương thức tương ứng khi sự kiện xảy ra. Vì hầu hết interface listener chỉ có một phương thức trừu tượng (functional interface), bạn có thể viết bằng lambda ngắn gọn thay vì tạo cả một lớp: 

JButton button = new JButton("Lưu");
button.addActionListener(e -> {
    // code xử lý khi bấm nút, chạy ngay trên EDT
    System.out.println("Đã bấm Lưu");
});

2. Khi interface có nhiều hơn 1 phương thức

MouseListener có 5 phương thức trừu tượng (mouseClicked, mousePressed, mouseReleased, mouseEntered, mouseExited) — không phải functional interface nên không dùng lambda trực tiếp được. Swing cung cấp sẵn lớp MouseAdapter (cài đặt rỗng cho cả 5), bạn chỉ cần kế thừa và override đúng cái mình cần: 

table.addMouseListener(new MouseAdapter() {
    @Override
    public void mouseClicked(MouseEvent e) {
        if (e.getClickCount() == 2) {
            // double-click — mở form sửa dòng đang chọn
        }
    }
});

Cùng ý tưởng đó áp dụng cho ListSelectionListener (theo dõi dòng bảng đang chọn thay đổi) — thường dùng để bật/tắt một nút tuỳ theo có dòng nào đang được chọn hay không:

table.getSelectionModel().addListSelectionListener(e -> {
    deleteButton.setEnabled(table.getSelectedRow() >= 0);
});

3. Nói chuyện lại với người dùng: JOptionPane

Ba tình huống phổ biến nhất:

// Báo lỗi
JOptionPane.showMessageDialog(parent, "Tên không được để trống", "Lỗi", JOptionPane.ERROR_MESSAGE);

// Hỏi Có/Không
int choice = JOptionPane.showConfirmDialog(parent, "Xoá dòng này?", "Xác nhận", JOptionPane.YES_NO_OPTION);
if (choice == JOptionPane.YES_OPTION) { /* xoá */ }

// Nhập nhanh 1 giá trị
String name = JOptionPane.showInputDialog(parent, "Nhập tên:");
// name == null nếu người dùng bấm Cancel — luôn kiểm tra trước khi dùng

4. Form nhiều ô nhập trong một hộp thoại

JOptionPane không giới hạn ở text đơn giản — tham số message có thể là bất kỳ component nào, kể cả một JPanel chứa nhiều ô nhập. Đây là cách dựng một "form dialog" đầy đủ mà không cần tự viết lớp con của JDialog: 

JTextField nameField = new JTextField();
JTextField emailField = new JTextField();

JPanel form = new JPanel(new GridLayout(2, 2, 8, 8));
form.add(new JLabel("Tên:"));
form.add(nameField);
form.add(new JLabel("Email:"));
form.add(emailField);

int result = JOptionPane.showConfirmDialog(parent, form, "Thêm người dùng", JOptionPane.OK_CANCEL_OPTION);
if (result == JOptionPane.OK_OPTION) {
    String name = nameField.getText();
    String email = emailField.getText();
    // validate rồi lưu
}
Lỗi hay gặp Không validate dữ liệu trước khi lưu, để exception từ tầng dưới (service/DB) bay thẳng lên và hiện stack trace thô cho người dùng. Luôn bọc lời gọi lưu trong try/catch, và hiện lỗi qua showMessageDialog thay vì để chương trình "vỡ" giữa chừng.

Kiểm tra nhanh

1. Interface nào bạn dùng để phản ứng khi người dùng bấm một JButton?

Đúng — ActionListener là interface chuẩn cho "hành động cấp cao" như bấm nút, chọn combo box, Enter trong ô nhập.
Chưa đúng — các listener kia dùng cho sự kiện chuột thô, phím thô, hoặc sự kiện cửa sổ, không phải cho nút bấm.

2. MouseListener có 5 phương thức trừu tượng. Để chỉ cần override đúng 1 cái mình cần, cách gọn nhất là gì?

Đúng — MouseAdapter đã cài sẵn cả 5 phương thức (rỗng), bạn chỉ cần override cái cần dùng.
Chưa đúng — không cần cài đặt thủ công hay viết lại interface, Swing đã có sẵn lớp tiện ích cho việc này.

3. Muốn hiển thị một form gồm nhiều ô nhập bên trong một hộp thoại OK/Cancel bằng JOptionPane, cách làm đúng là gì?

Đúng — tham số message của showConfirmDialog nhận bất kỳ component nào, kể cả một JPanel chứa cả form.
Chưa đúng — không cần gọi nhiều lần hay xếp chồng dialog; JOptionPane đã hỗ trợ nhận cả một panel làm nội dung.

Bài tập thực hành

Tiếp tục từ ứng dụng Book/JTable ở Bài 3 (nếu chưa làm Bài 3, dựng lại nhanh một bảng tương tự với 2-3 field).

  1. Thay nút "In sách đã chọn" bằng hành vi thật: khi bấm mà chưa chọn dòng nào, hiện showMessageDialog báo "Vui lòng chọn một dòng" (ERROR_MESSAGE). Khi đã chọn, hiện showConfirmDialog hỏi "Xoá quyển [tên sách]?" — nếu chọn Yes thì xoá khỏi danh sách và gọi lại setRows(...)/fireTableDataChanged() để bảng cập nhật.
  2. Thêm nút "Thêm sách mới" mở một form dialog (theo đúng mẫu mục 4) với 3 ô nhập tương ứng 3 field của Book. Khi OK, validate tối thiểu (tên sách không được trống — nếu trống, hiện lỗi và không đóng luồng thêm sách, để người dùng sửa lại) rồi thêm vào danh sách và cập nhật bảng.
  3. Gắn thêm double-click vào một dòng (dùng MouseAdapter theo mục 2) để mở lại đúng form đó, nhưng đã điền sẵn dữ liệu của dòng được chọn, cho phép sửa.
  4. Tự kiểm tra:
    • [ ] Xoá khi chưa chọn dòng nào không làm crash, chỉ hiện thông báo nhắc chọn.
    • [ ] Thêm sách với tên trống bị chặn lại, có thông báo lỗi rõ ràng.
    • [ ] Double-click một dòng mở đúng form sửa với dữ liệu điền sẵn, không phải form trống.
  5. Áp dụng vào project của bạn: đây chính là bộ ba "list → dialog thêm/sửa → dialog xác nhận xoá" sẽ lặp lại ở hầu hết mọi màn hình quản lý dữ liệu trong ứng dụng thật của bạn. Cân nhắc viết 2-3 hàm tiện ích dùng chung (ví dụ một hàm showForm(...) nhận vào danh sách field cần nhập) để không phải viết lại GridLayout + showConfirmDialog mỗi lần.
Đừng ngại hỏi Việc kết hợp form dialog + validate + cập nhật bảng có khá nhiều bước nhỏ dễ quên một bước — nếu có bước nào không hoạt động như mong đợi, dán code ra để được rà lại từng bước.
