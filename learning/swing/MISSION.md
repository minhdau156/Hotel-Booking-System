# Mission: Java Swing

## Why
The user is part of a 5-person team building a desktop app with Java Swing and has no prior Swing experience. They want to actually learn Swing as a skill — general, durable knowledge of the toolkit — rather than a narrow cheat-sheet wired to one specific project's file names and task numbers.

## Success looks like
- Understands core Swing concepts: `JFrame`/`JDialog` windows, the Event Dispatch Thread, the common layout managers, the standard components (buttons, text fields, tables, combo boxes, spinners, dialogs), and the event-listener model.
- Can build a Swing screen from scratch without needing to copy a pre-written template — knows which component/layout to reach for and why.
- Retains this knowledge long-term (storage strength), not just well enough to pass a quiz in the moment.

## Constraints
- Prefers general Swing knowledge over project-specific instructions — explicitly asked not to tie lessons too closely to the hotel booking project. Lessons should stand on their own as "how Swing works," with the project only as occasional, light illustration if it helps, never as the organizing structure.
- Lesson content (lessons/reference docs) is written in Vietnamese; meta-files (this file, RESOURCES.md, NOTES.md, learning records) stay in English.
- Time-boxed, alongside other coursework — lessons should stay short and focused.

## Out of scope
- Swing look-and-feel theming / custom `LookAndFeel`.
- `SwingWorker` / background-thread UI patterns (can revisit later if it becomes relevant).
- JavaFX or other GUI toolkit comparisons.
- Deep-diving the hotel booking project's own file structure or task list as the primary teaching vehicle.
